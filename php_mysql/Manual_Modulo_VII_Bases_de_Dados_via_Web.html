Bases de Dados via Web, do zero ao painel de gestão

Este manual leva-te, passo a passo, desde criar a tua primeira conta e repositório no GitHub até teres um painel de administração completo — com login, gestão de categorias e produtos — a correr dentro de um GitHub Codespace, usando Docker, PHP 8 e MySQL. Nunca usaste nenhuma destas ferramentas? Ótimo: este manual foi escrito a pensar em ti.

🧭 Como usar este manual

Está dividido em 14 blocos, pela ordem exata em que deves fazê-los — cada um assume que o anterior já está concluído. O índice à esquerda mostra quanto tempo cada bloco costuma demorar; vai marcando as caixinhas ✓ à medida que avanças (fica guardado neste teu browser). Sempre que vires uma etiqueta amarela por cima de um bloco de código, é o nome do ficheiro onde esse código deve ficar.

O que vais ter construído no final

  • Um repositório no GitHub com um ambiente de programação 100% pronto a usar (Docker + PHP 8 + MySQL + phpMyAdmin), que qualquer colega consegue abrir num Codespace e pôr a funcionar em minutos.
  • Uma base de dados com uma tabela de administradores e uma conta inicial (admin / 123).
  • Duas tabelas construídas por ti — categorias e produtos — relacionadas entre si, criadas tanto por phpMyAdmin como por código SQL.
  • Um painel de gestão protegido por login, com operações completas de listar / inserir / editar / eliminar (o chamado CRUD) para categorias, produtos e administradores.

Bloco 1

Criar o repositório no GitHub

⏱ 1h00

Objetivo: ter uma conta no GitHub e um repositório vazio, pronto para receber o teu projeto.

1.1 — O que é o GitHub e o que é um repositório?

O GitHub é um site onde se guarda código e se trabalha em equipa, usando a ferramenta Git para controlar as versões dos ficheiros (é possível voltar atrás no tempo e ver quem alterou o quê). Um repositório ("repo") é simplesmente a "pasta do projeto" guardada no GitHub — é lá que vai viver todo o código deste módulo.

Bloco 2

Abrir o GitHub Codespace

⏱ 1h00

2.1 — O que é um Codespace?

Um GitHub Codespace é um computador completo (uma máquina virtual Linux), criado automaticamente na nuvem pelo GitHub, com um editor de código (o Visual Studio Code) a correr dentro do teu browser. Não precisas de instalar nada: abres o Codespace e tens logo um terminal, um explorador de ficheiros e um editor — tudo ligado ao teu repositório.

🧠 Vale a pena saber

Cada conta gratuita do GitHub tem um número de horas grátis de Codespaces por mês (mais do que suficiente para este módulo). Quando fechas o browser, o Codespace fica "parado" (não continua a gastar horas) e retomas exatamente onde ficaste da próxima vez que o abrires.

Bloco 3

Docker explicado, container a container

⏱ 2h00

Objetivo: perceber o que é o Docker e criar os ficheiros que descrevem o nosso ambiente (ainda sem o ligar).

3.1 — Imagem, container e serviço: três palavras-chave

  • Imagem — uma "receita" pronta com um programa já instalado e configurado (ex.: uma imagem do MySQL já traz o MySQL instalado). Descarrega-se de um catálogo público (o Docker Hub).
  • Container — uma imagem posta a correr. É como uma pequena "caixa" isolada, com o seu próprio sistema de ficheiros, a correr dentro do Codespace, sem interferir com o resto.
  • docker-compose.yml — um ficheiro de configuração que descreve vários containers ao mesmo tempo (os nossos serviços) e como eles comunicam entre si, para os ligarmos todos com um único comando.

Vamos precisar de três containers a trabalhar em equipa:

Repara: o teu browser só fala diretamente com o web (porta 8000) e com o phpmyadmin (porta 8080). O MySQL (db) nunca é acedido diretamente pelo browser — só os outros dois containers lhe falam, através da rede interna que o Docker cria automaticamente entre eles.

3.2 — Criar a pasta e o ficheiro docker-compose.yml

No Explorer do Codespace (painel esquerdo), clica com o botão direito em cima do nome do repositório → New File → escreve docker-compose.yml e cola este conteúdo:

docker-compose.yml 
version: "3.8"

services:

  # Servidor web com PHP 8 (Apache + PHP), onde vive o nosso site
  web:
    build: ./web
    volumes:
      - ./www:/var/www/html
    ports:
      - "8000:80"
    depends_on:
      - db

  # Servidor de base de dados MySQL
  db:
    image: mysql:8.0
    environment:
      MYSQL_ALLOW_EMPTY_PASSWORD: "yes"
      MYSQL_DATABASE: bd_produtos
    volumes:
      - db_data:/var/lib/mysql
      - ./sql/init.sql:/docker-entrypoint-initdb.d/init.sql:ro
    ports:
      - "3306:3306"

  # phpMyAdmin - interface gráfica para administrar o MySQL
  phpmyadmin:
    image: phpmyadmin/phpmyadmin
    environment:
      PMA_HOST: db
      PMA_PORT: 3306
    ports:
      - "8080:80"
    depends_on:
      - db

volumes:
  db_data:

O que significa cada parte:

LinhaO que faz
build: ./webConstrói uma imagem à medida a partir do web/Dockerfile (vamos criá-lo a seguir), em vez de usar uma imagem pronta.
image: mysql:8.0Usa diretamente a imagem oficial do MySQL versão 8, descarregada do Docker Hub.
volumesLiga uma pasta do Codespace a uma pasta dentro do container. ./www:/var/www/html significa: "tudo o que eu editar na pasta www aparece logo dentro do container web". db_data guarda os dados do MySQL para não se perderem se o container reiniciar.
ports: "8000:80"Liga a porta 8000 do Codespace à porta 80 (a porta normal da Web) de dentro do container.
environmentVariáveis passadas ao container quando arranca — aqui usamos para já criar a base de dados bd_produtos e dizer ao phpMyAdmin onde fica o MySQL (PMA_HOST: db — repara que usamos o nome do serviço, não "localhost"!).
depends_onDiz ao Docker para só arrancar este container depois do db já ter arrancado.
⚠️ Cuidado com a indentação

Ficheiros .yml usam espaços (nunca tabs) para organizar a hierarquia. Se colares o código de cima tal como está, não precisas de mexer em nada — mas se fores escrever à mão, mantém sempre 2 espaços por nível.

3.3 — Criar o Dockerfile do serviço web

A imagem oficial php:8.2-apache já traz o PHP 8 e o Apache, mas falta-lhe uma peça: a extensão mysqli, que é a "linguagem" que o PHP usa para falar com o MySQL. Por isso construímos a nossa própria imagem, a partir dela.

Cria a pasta web e, dentro dela, um ficheiro chamado Dockerfile (sem extensão):

web/Dockerfile 
# Imagem base: PHP 8 já com o Apache incluído
FROM php:8.2-apache

# Instala a extensão mysqli (necessária para falar com o MySQL)
RUN docker-php-ext-install mysqli pdo pdo_mysql

WORKDIR /var/www/html

Em português simples: "parte da imagem php:8.2-apache, instala nela a extensão mysqli, e define a pasta de trabalho". É isto que dizemos que "o Docker já vem pronto": não precisas de instalar PHP nem Apache manualmente — só de descrever o que queres, uma vez.

3.4 — Criar a pasta sql e o dump inicial

Cria a pasta sql e dentro dela o ficheiro init.sql. Este ficheiro é o dump inicial: corre automaticamente da primeira vez que o container do MySQL é criado, e prepara a base de dados com a tabela de administradores já pronta.

sql/init.sql 
CREATE DATABASE IF NOT EXISTS bd_produtos
    CHARACTER SET utf8mb4
    COLLATE utf8mb4_unicode_ci;

USE bd_produtos;

-- Tabela de administradores (quem pode entrar no painel)
CREATE TABLE IF NOT EXISTS administradores (
    id            INT AUTO_INCREMENT PRIMARY KEY,
    utilizador    VARCHAR(50)  NOT NULL UNIQUE,
    password      VARCHAR(255) NOT NULL,
    nome          VARCHAR(100) NOT NULL,
    data_criacao  TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- Conta de administrador inicial: utilizador "admin", password "123"
-- (a password nunca fica visível: é guardada com um hash bcrypt)
INSERT INTO administradores (utilizador, password, nome)
VALUES (
    'admin',
    '$2y$12$Z55U/2KoLdNKmHfcD6lu1.Rc3t26pJDwWasx8tyBgrsTaYteXnB1G',
    'Administrador'
);
🔐 Porque é que a password não aparece "123"?

Guardar passwords em texto simples é uma má prática grave de segurança. Em vez disso, guardamos um hash (uma "impressão digital" irreversível) gerado pela função PHP password_hash("123", PASSWORD_BCRYPT). No Bloco 7, quando fizermos o login, vamos usar password_verify() para confirmar que a password escrita corresponde a este hash, sem nunca precisarmos de saber a password original.

✅ Confirma antes de avançar

No Explorer devias ter agora: docker-compose.yml, web/Dockerfile e sql/init.sql. Ainda não vamos arrancar nada — isso é já no próximo bloco.

Bloco 4

Arrancar o ambiente e testar as portas

⏱ 2h00

Objetivo: pôr os três containers a correr, criar uma página de teste e perceber portas públicas vs. privadas.

4.1 — Criar a página de teste

Antes de arrancar, cria a pasta www (é para lá que aponta o volume ./www:/var/www/html do docker-compose). Dentro dela, cria estes dois ficheiros:

www/db.php 
<?php
/**
 * Ficheiro central de ligação à base de dados.
 * Todos os outros ficheiros PHP fazem: require 'db.php';
 */
$servidor   = 'db';   // nome do SERVIÇO no docker-compose.yml, não é "localhost"!
$utilizador = 'root';
$password   = '';     // sem password (MYSQL_ALLOW_EMPTY_PASSWORD) - só para aprendizagem!
$basedados  = 'bd_produtos';

$ligacao = mysqli_connect($servidor, $utilizador, $password, $basedados);

if (!$ligacao) {
    die('Erro de ligação à base de dados: ' . mysqli_connect_error());
}
mysqli_set_charset($ligacao, 'utf8mb4');
💡 A diferença mais importante para quem já usou XAMPP

Nos exemplos antigos (XAMPP), a ligação era sempre mysqli_connect('localhost', 'root'), porque o PHP e o MySQL corriam no mesmo computador. Aqui correm em containers diferentes, por isso usamos o nome do serviço definido no docker-compose (db) em vez de localhost. É a única mudança de mentalidade que precisas de fazer!

www/index.php 
<?php
// Página de teste: confirma que o PHP e o MySQL estão a funcionar
try {
    require 'db.php';
    $bd_ok = true;
} catch (Throwable $e) {
    $bd_ok = false;
}
?>
<h1>Página de teste do ambiente</h1>
<p>PHP: <?php echo phpversion(); ?> — a funcionar!</p>
<p>Base de dados:
<?php echo $bd_ok ? 'ligação com sucesso!' : 'falhou.'; ?>
</p>
<p><a href="info.php">Ver phpinfo()</a></p>

E também um ficheiro www/info.php só com <?php phpinfo(); ?> — mostra toda a configuração do PHP instalado (útil para confirmares a versão e as extensões ativas, como a mysqli).

4.2 — Arrancar os containers

No terminal do Codespace, escreve:

docker compose up -d --build

Traduzindo o comando: up arranca os serviços descritos no docker-compose.yml; --build obriga a construir a imagem do web a partir do teu Dockerfile; -d corre tudo em segundo plano (detached), devolvendo-te o terminal. Na primeira vez demora 1 a 2 minutos (está a descarregar as imagens do MySQL, phpMyAdmin e PHP). Para confirmar que os três estão a correr:

docker compose ps

Devias ver três linhas, todas com o estado running (ou Up): uma para web, uma para db e uma para phpmyadmin.

⚠️ Se algo não arrancar

Corre docker compose logs db (ou web, ou phpmyadmin) para ver as mensagens de erro desse container específico. O erro mais comum nesta fase é um espaço mal colocado no docker-compose.yml — revê a indentação.

Bloco 6

SQL essencial: SELECT, INSERT, UPDATE, DELETE

⏱ 3h00

Objetivo: dominar as quatro instruções SQL que vais usar em todo o projeto, praticando no separador SQL do phpMyAdmin.

SQL (Structured Query Language) é a linguagem universal para falar com bases de dados relacionais como o MySQL. Só precisas destas quatro instruções para tudo o que vamos fazer:

6.1 — SELECT (ler dados)

SQL 
-- todas as colunas, todas as linhas
SELECT * FROM administradores;

-- só algumas colunas
SELECT utilizador, nome FROM administradores;

-- com uma condição (WHERE)
SELECT * FROM administradores WHERE utilizador = 'admin';

-- ordenado
SELECT * FROM administradores ORDER BY nome ASC;

* significa "todas as colunas". WHERE filtra as linhas. ORDER BY coluna ASC|DESC ordena o resultado (crescente/decrescente).

6.2 — INSERT (criar dados)

SQL 
INSERT INTO administradores (utilizador, password, nome)
VALUES ('teste', '1234', 'Utilizador de Teste');

Não indicamos a coluna id porque é AUTO_INCREMENT — o MySQL atribui-lhe um número automaticamente.

6.3 — UPDATE (alterar dados)

SQL 
UPDATE administradores
SET nome = 'Utilizador Alterado'
WHERE utilizador = 'teste';
⚠️ Nunca esqueças o WHERE

Um UPDATE ou DELETE sem WHERE aplica-se a todas as linhas da tabela. É um dos erros mais comuns (e mais dolorosos) em SQL — habitua-te a escrever sempre o WHERE primeiro e só depois preencher o resto.

6.4 — DELETE (apagar dados)

SQL 
DELETE FROM administradores WHERE utilizador = 'teste';

6.5 — Onde experimentar

Vai ao phpMyAdmin (porta 8080) → base de dados bd_produtos → separador SQL (no topo, depois de entrares na base de dados). Cola qualquer uma das instruções acima e clica em Executar. Podes sempre confirmar o resultado no separador Procurar da tabela.

✅ Exercício — pratica as quatro instruções

Na base de dados bd_produtos, pelo separador SQL:

  1. Insere um segundo administrador (usa um utilizador diferente de "admin").
  2. Lista todos os administradores ordenados por nome.
  3. Atualiza o nome desse administrador que acabaste de criar.
  4. Elimina-o (para não ficar lixo na base de dados).
  5. Confirma no fim que só resta o admin original.

6.6 — Um adiantamento: o mesmo SQL, dentro do PHP

No próximo bloco vamos usar exatamente estas mesmas instruções, mas escritas dentro de código PHP em vez de coladas diretamente no phpMyAdmin. O padrão é sempre o mesmo:

exemplo.php 
$consulta = "SELECT * FROM administradores WHERE utilizador = ?";
$stmt = mysqli_prepare($ligacao, $consulta);
mysqli_stmt_bind_param($stmt, 's', $utilizador);
mysqli_stmt_execute($stmt);
$resultado = mysqli_stmt_get_result($stmt);

Repara que, em vez de escrever o valor diretamente dentro do texto SQL, usamos um ? (um "placeholder") e passamos o valor à parte, com mysqli_stmt_bind_param. Chama-se um prepared statement e é a forma segura de construir SQL com dados escritos por um utilizador — evita um ataque chamado SQL injection, em que alguém tenta escrever SQL malicioso dentro de uma caixa de texto do teu formulário.

Bloco 7

Sistema de login

⏱ 3h00

Objetivo: construir o ecrã de login (sem registo) que verifica o utilizador/password na base de dados.

Bloco 8

Criar as tabelas categorias e produtos

⏱ 3h00

Objetivo: desenhar e criar duas tabelas relacionadas — a primeira vez por phpMyAdmin, a segunda por código SQL.

8.1 — O desenho da relação

Cada produto pertence a uma categoria, mas cada categoria pode ter vários produtos. Chama-se uma relação um-para-muitos (1:N). Implementa-se acrescentando à tabela "do lado N" (produtos) uma coluna que aponta para o id da tabela "do lado 1" (categorias) — chamamos-lhe chave estrangeira (foreign key, ou FK).

erDiagram
  CATEGORIAS ||--o{ PRODUTOS : "tem"
  CATEGORIAS {
    int id PK
    varchar nome
  }
  PRODUTOS {
    int id PK
    varchar nome
    decimal preco
    int categoria_id FK
  }

8.3 — Método B: criar "produtos" por código SQL

Desta vez, em vez de usar o formulário, vamos escrever o SQL diretamente no separador SQL do phpMyAdmin. Tenta primeiro sozinho, usando o Bloco 6 e o diagrama acima como referência — só depois compara com a solução abaixo.

✅ Exercício — antes de veres a solução

Escreve o CREATE TABLE produtos com as colunas: id (chave primária, automática), nome (texto até 150 caracteres), preco (número com 2 casas decimais) e categoria_id (número inteiro, que vai ligar a categorias.id).

SQL 
CREATE TABLE produtos (
    id            INT AUTO_INCREMENT PRIMARY KEY,
    nome          VARCHAR(150) NOT NULL,
    preco         DECIMAL(10,2) NOT NULL DEFAULT 0,
    categoria_id  INT,
    CONSTRAINT fk_produtos_categoria
        FOREIGN KEY (categoria_id) REFERENCES categorias(id)
        ON DELETE SET NULL
);
ParteExplicação
DECIMAL(10,2)Número com até 10 dígitos, sendo 2 depois da vírgula — ideal para preços (evita erros de arredondamento que os tipos float têm).
FOREIGN KEY … REFERENCES categorias(id)Diz ao MySQL: "categoria_id tem de corresponder sempre a um id que exista na tabela categorias" (ou ser vazio). Impede-te de inserir um produto com uma categoria inexistente.
ON DELETE SET NULLSe uma categoria for apagada, os produtos que lhe pertenciam não são apagados — ficam apenas sem categoria (categoria_id passa a NULL).
⚠️ Pré-requisito para FOREIGN KEY

As chaves estrangeiras só funcionam em tabelas do motor InnoDB (é o motor pré-definido no MySQL 8, por isso normalmente não precisas de fazer nada — mas se vires um erro "errno: 150", confirma em Estrutura → Operações que o "Motor de armazenamento" de ambas as tabelas é InnoDB).

Bloco 11

Gerir Administradores (CRUD)

⏱ 2h00

Objetivo: fechar o ciclo, permitindo criar novos administradores em vez de só termos o "admin" inicial.

É o terceiro CRUD do manual, com a mesma estrutura de sempre — mas com duas particularidades importantes: as passwords têm de ser encriptadas antes de gravar, e um administrador não se pode eliminar a si próprio (ou ficaria sem acesso ao painel).

11.1 — Inserir, com password_hash()

www/administradores_inserir.php 
<?php
require 'protege.php';
require 'db.php';

$nome       = trim($_POST['nome'] ?? '');
$utilizador = trim($_POST['utilizador'] ?? '');
$password   = $_POST['password'] ?? '';

if ($nome === '' || $utilizador === '' || strlen($password) < 4) {
    header('Location: administradores_novo.php');
    exit;
}

// NUNCA guardar a password em texto simples: usa-se password_hash()
$password_hash = password_hash($password, PASSWORD_BCRYPT);

$consulta = "INSERT INTO administradores (utilizador, password, nome) VALUES (?, ?, ?)";
$stmt = mysqli_prepare($ligacao, $consulta);
mysqli_stmt_bind_param($stmt, 'sss', $utilizador, $password_hash, $nome);
mysqli_stmt_execute($stmt);

header('Location: administradores_listar.php');
exit;

É a mesma função que já viste no sql/init.sql a gerar o hash da password "123" — agora usada diretamente em PHP, para cada novo administrador que criares.

11.2 — Editar sem obrigar a mudar a password

No formulário de edição, o campo de password fica vazio por defeito (nunca mostramos o hash) e é opcional — só se o utilizador escrever algo é que a password é alterada:

www/administradores_actualizar.php 
<?php
require 'protege.php';
require 'db.php';

$id         = (int) ($_POST['id'] ?? 0);
$nome       = trim($_POST['nome'] ?? '');
$utilizador = trim($_POST['utilizador'] ?? '');
$password   = $_POST['password'] ?? '';

if ($password !== '') {
    // Alterou a password: atualiza também o hash
    $password_hash = password_hash($password, PASSWORD_BCRYPT);
    $consulta = "UPDATE administradores SET nome=?, utilizador=?, password=? WHERE id=?";
    $stmt = mysqli_prepare($ligacao, $consulta);
    mysqli_stmt_bind_param($stmt, 'sssi', $nome, $utilizador, $password_hash, $id);
} else {
    // Não mexeu na password: mantém a que já estava
    $consulta = "UPDATE administradores SET nome=?, utilizador=? WHERE id=?";
    $stmt = mysqli_prepare($ligacao, $consulta);
    mysqli_stmt_bind_param($stmt, 'ssi', $nome, $utilizador, $id);
}
mysqli_stmt_execute($stmt);
header('Location: administradores_listar.php');
exit;

11.3 — Eliminar, exceto a própria conta

www/administradores_eliminar.php 
<?php
require 'protege.php';
require 'db.php';

$id = (int) ($_GET['id'] ?? 0);

// Não deixa o administrador eliminar a própria conta
if ($id > 0 && $id !== (int) $_SESSION['admin_id']) {
    $consulta = "DELETE FROM administradores WHERE id = ?";
    $stmt = mysqli_prepare($ligacao, $consulta);
    mysqli_stmt_bind_param($stmt, 'i', $id);
    mysqli_stmt_execute($stmt);
}
header('Location: administradores_listar.php');
exit;

Repara na condição $id !== (int) $_SESSION['admin_id'] — usa a sessão criada em autenticar.php (Bloco 7) para saber quem está ligado, e recusa o pedido se for a própria conta. Na listagem (administradores_listar.php), a mesma verificação é usada para simplesmente não mostrar o link "Eliminar" ao lado da tua própria conta.

⚠️ Reflexão sobre segurança (bom para a parte cognitiva da avaliação)

Neste projeto de aprendizagem usamos root sem password para o MySQL, para simplificar. Num sistema real em produção, nunca farias isto: usarias um utilizador de base de dados dedicado, com password forte, e permissões limitadas apenas ao estritamente necessário.

Bloco 13

Publicar no GitHub

⏱ 2h00

Objetivo: gravar (commit) e enviar (push) o teu trabalho para o GitHub, para ficar guardado e disponível para avaliação.

13.1 — Porque é que isto é importante

Tudo o que fizeste até agora vive dentro do Codespace. Se nunca fizeres commit e push, o teu código nunca chega ao repositório no GitHub — e é lá que o teu professor vai avaliar o trabalho. Devias fazer isto com frequência (não só no final!), sempre que terminares uma funcionalidade que funciona.

13.2 — Pelo terminal

git add .
git commit -m "Painel completo: login, categorias, produtos e administradores"
git push
ComandoO que faz
git add .Marca todos os ficheiros alterados/novos para serem incluídos no próximo commit
git commit -m "…"Cria um "ponto de gravação" com uma mensagem a descrever o que mudou
git pushEnvia os commits guardados localmente para o GitHub

13.3 — Pela interface gráfica (Source Control)

Alternativa sem escrever comandos: no menu lateral esquerdo do VS Code, clica no ícone de Source Control (parece três círculos ligados por linhas). Vês a lista de ficheiros alterados — clica no + junto de cada um (ou passa o rato sobre "Changes" e clica no + geral) para os preparar, escreve uma mensagem na caixa de texto no topo, e clica em Commit. Depois clica em Sync Changes (ou "Push") para enviar para o GitHub.

💡 Porque é que a base de dados não "desaparece" com o commit?

Os dados que inseriste (categorias, produtos…) vivem dentro do volume Docker db_data, que não é enviado para o GitHub — só o código vai (docker-compose.yml, os .php, o init.sql). Isto é normal e correto: sempre que alguém abrir um Codespace novo a partir do teu repositório, a base de dados recomeça do zero, com o dump inicial (Bloco 5). Os dados de teste que inseriste manualmente não seguem — só a estrutura que criaste por SQL, se a tiveres também guardado nalgum ficheiro .sql.

⚠️ git push pede utilizador/password?

Dentro de um Codespace normalmente não é preciso configurar nada — a autenticação já vem tratada automaticamente pelo GitHub. Se ainda assim aparecer um pedido de autorização no browser, aceita-o (é o GitHub a confirmar que és tu).

✅ Confirma antes de terminar

Abre o teu repositório no GitHub (fora do Codespace, no site normal) e confirma que todos os ficheiros lá estão: docker-compose.yml, web/, sql/ e www/ com todas as páginas PHP.
